# Phase 8: Jira Tracking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only, incrementally synced view of the user's in-scope Jira issues, with deterministic attention rules, Slack-mention correlation, an API, and a dashboard section and Needs-you card.

**Architecture:** A `jira/claude-connector` adapter runs one collector run per page through the orchestrator, trusting only the raw tool_result and checking that it matches the requested arguments. A `jira-tracking` module stores the issues and applies the rules. Workers handle the cloudId, incremental sync and daily reconcile. The web gets one new section.

**Tech Stack:** Bun 1.4.4, TypeScript strict, Hono, bun:sqlite + Drizzle (generated migrations), Zod 4, Next.js 16, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-06-phase-8-jira.md` (connector facts and decisions B1–B14). Module design: `docs/modules/jira.md`.

## Global Constraints

- **Repo data:** no real project keys, site names, cloudIds, issue keys or summaries anywhere in the repo. Tests use the synthetic project `DEMO` (`DEMO-1`…) and an excluded project `SKIP`. The cloudId is `00000000-0000-4000-8000-000000000000`.
- **Hard rules (CLAUDE.md):**
  - Only the orchestrator runs Claude.
  - Only raw tool_results are trusted.
  - Jira text is untrusted and never reaches a run that can act.
  - No Jira text in logs, audit rows, events, errors or `lastError`. Events carry keys only.
- **Tools:**
  - Collection allows exactly `mcp__claude_ai_Atlassian__searchJiraIssuesUsingJql` and `ToolSearch`.
  - CloudId resolution allows exactly `mcp__claude_ai_Atlassian__getAccessibleAtlassianResources` and `ToolSearch`.
  - Profile `collector`, model haiku. The other Atlassian server and every write tool are denied by the existing denylist rules.
- **Dependencies:** no new dependency.
- **Migrations:** one new migration, `0015_jira.sql`. Check that the latest number is 0014 first.
- **Checks:** `bun run check` stays green, and web tasks also pass `bun run --cwd apps/web build`.

## Review Focus

1. **A page whose tool_use input differs from the requested arguments**, for example a model-altered JQL that drops the exclusion. The run fails and nothing is stored. Test in Task 2.
2. **Reconcile that fails mid-way.** No issue changes scope. Test in Task 3.
3. **An excluded project appears in the results anyway.** It is dropped before storage. Test in Task 3.
4. **The timestamp offset `+0530`** parses to the correct UTC instant, and the checkpoint arithmetic uses instants. Test in Task 1.
5. **Jira disabled, or no cloudId.** No job runs Claude, and the web shows the setup card. Tests in Tasks 3 and 5.

### Task 2: Connector adapter (`integrations/jira`)

**Files:**
- Create: `apps/api/src/integrations/jira/connector-source.ts`. `JiraConnectorSource`, with deps `{ orchestrator, clock }`, exposes:
  - `resolveCloudId(signal): Promise<{ id; url; name }[]>`;
  - `searchPage(args: { cloudId; jql; maxResults; nextPageToken?: string }, signal): Promise<{ issues; nextPageToken; total }>`.

  Each method is one orchestrator `run` with `workerProfile: "collector"`, `priorityClass: "collection"`, model `haiku`, `maxTurns: 4`, the allowed tools from Global Constraints, and instructions with the exact JSON arguments (`fields` = `JIRA_FIELDS`). Trust (spec B3):
  - Use only `result.toolResults` entries for the expected tool.
  - Require exactly one non-error result whose `input` equals the requested arguments: same keys and values, `fields` compared as a set, and `nextPageToken` absent when not requested. An extra `responseContentFormat` or `actionSource` key is tolerated only when it equals `"markdown"` / `"model_tool_call"`.
  - Otherwise throw a `JobError` of kind `incomplete_ai_output` with a fixed message.
- Test: `apps/api/test/integrations/jira-connector-source.test.ts`. Use a fake orchestrator returning crafted `toolResults`.

**Interfaces:**
- Consumes: Task 1 parse functions and constants.
- Produces: the `JiraConnectorSource` methods above.

Each schedule runs only while `jira.enabled`, and sync and reconcile only when the cloudId is set. Follow how the Slack incremental and retention jobs are scheduled. Use the sync-state stream `jira.issues` (for the checkpoint and `lastError`) and `jira.reconcile`.
- Test: `apps/api/test/modules/jira-tracking.test.ts` and `apps/api/test/workers/jira-sync.test.ts`, with a fake `JiraConnectorSource`.

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces: `JiraService` and the job types `jira.resolve_cloud_id`, `jira.sync_incremental` and `jira.reconcile`.

- [ ] **Step 1: Write the failing tests.**
  - **JQL:**
    - `incrementalJql("assignee = currentUser() AND updated >= -60d", ["SKIP"], 17)` equals `"(assignee = currentUser() AND updated >= -60d) AND project not in (SKIP) AND updated >= -17m ORDER BY updated ASC"`;
    - with no exclusions there is no `project not in` clause;
    - minutes are capped at `windowDays*1440`.
  - **Attention:** one case per rule, in priority order. Done issues give null. Out-of-scope issues give null. Boundaries: due today is `due_soon`, not `overdue`; `stale` triggers at exactly `stale.days`.
  - **Store:**
    - re-upserting an unchanged issue publishes no event;
    - a status change publishes `jira.issue_updated`;
    - an attention change to non-null publishes `jira.issue_attention`;
    - an excluded project is dropped.
  - **Sync:**
    - the first run uses the full window;
    - three pages with `maxPagesPerRun` 2 enqueue a continuation with the token;
    - the checkpoint is committed only after the last page;
    - a page failure leaves the checkpoint unchanged and records `lastError` (kind only).
  - **Reconcile:** a complete run marks unseen issues out of scope. A run failing on page 2 changes no flags.
  - **CloudId:** one site is stored. Two sites give `NEEDS_ATTENTION` `multiple_sites`. Disabled means nothing is enqueued.
  - **Slack mentions:** `DEMO-12` matches "fixing DEMO-12 now" but not "DEMO-123", and returns no text.

- [ ] **Step 3: Implement.**
