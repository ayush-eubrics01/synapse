# Phase 8: Jira Tracking — Design

**Authority:**

- `docs/modules/jira.md`, the module design.
- The user's scope decision (2026-11-06): track only issues assigned to the user in their chosen project, never another named project, within a rolling 2-month window. The real project keys live only in the local settings DB, never in the repo.
- ADR-026 (only raw tool results are trusted).
- ADR-032 (Jira text is untrusted).

## Connector facts (probed 2026-11-06 on the real connector; no content kept)

- `mcp__claude_ai_Atlassian__getAccessibleAtlassianResources` returns `[{ id (cloudId UUID), url, name, scopes[], avatarUrl }]`.
- `mcp__claude_ai_Atlassian__searchJiraIssuesUsingJql({ cloudId, jql, fields[], maxResults (50..100), nextPageToken?, searchResultMode? })` returns JSON:
  ```
  { issues: { totalCount?, nodes: [ { expand, id, key, self, webUrl, fields: {...} } ], webUrl, pageInfo: { hasNextPage, endCursor } },
    context: { atlassianAccountId, cloudId, ... } }
  ```
  - The next page passes `nextPageToken = pageInfo.endCursor`.
  - `totalCount` is present only with `searchResultMode: "all"` or `"count"`.
- Requested fields come back as:
  - `summary`: string
  - `status`: `{ name, statusCategory: { key: "new"|"indeterminate"|"done", name } }`
  - `priority`: `{ name }` or null
  - `issuetype`: `{ name, subtask }`
  - `project`: `{ key, name }`
  - `labels`: string[]
  - `duedate`: `"YYYY-MM-DD"` or null
  - `created` / `updated`: ISO-8601 with a numeric offset, e.g. `2026-09-14T10:49:18.071+0530`
- A page of 50 is about 120 KB of tool_result text.

## Scope

Phase 8 delivers a **read-only** sync of the user's in-scope issues, deterministic attention rules, Slack-mention correlation, API, and a dashboard section with a Needs-you card.

**Deferred** (listed in follow-ups):

- Jira writes (comment or transition through approval), in Phase 10 with engineering automation.
- Jira-sourced commitments.
- AI analysis (`jira.analyze`).
- The Engineering Brain links.

## Decisions

| # | Decision | Why |
|---|---|---|
| B1 | Settings and defaults: `jira.enabled` = false; `jira.cloudId` = null; `jira.scope.jql` = `assignee = currentUser() AND updated >= -60d`; `jira.excludedProjects` = []; `jira.sync.intervalMinutes` = 15; `jira.reconcile.hours` = 24; `jira.windowDays` = 60; `jira.stale.days` = 5; `jira.dueSoon.days` = 2; `jira.blockedStatuses` = []; `jira.pageSize` = 50; `jira.maxPagesPerRun` = 4 | The scope stays user data. The repo default is generic |
| B2 | The fields list is a code constant: `summary,status,priority,issuetype,project,labels,duedate,created,updated`. No `description` and no comments | Less untrusted text and smaller pages. Description and comments aren't needed for tracking |
| B3 | **One page per collector run.** The run is a collector profile on haiku. It allows exactly `[searchJiraIssuesUsingJql, ToolSearch]`, with `maxTurns: 4`. The instructions carry the exact JSON args. Trust rule: parse only the tool_result for that tool, and require its tool_use input to equal the requested `{cloudId, jql, fields, maxResults, nextPageToken?}`, compared by key after normalising array order for `fields`. Otherwise fail with `incomplete_ai_output`. A run with no matching tool_result is a failure | ADR-026. Mirrors the Slack collector's input check |
| B4 | **cloudId.** `jira.resolve_cloud_id` runs `getAccessibleAtlassianResources` once when `jira.cloudId` is null and `jira.enabled` is true. Exactly one resource is stored. More than one sets the job to `NEEDS_ATTENTION` with the reason `multiple_sites`: the user sets `jira.cloudId` by hand. Zero resources is the same, with `no_sites` | Deterministic, no guessing |
| B5 | **Incremental sync.** `jira.sync_incremental` runs every `intervalMinutes` while enabled and cloudId is set. JQL: `(<scope>) AND updated >= -<m>m ORDER BY updated ASC`, where `m = ceil(minutes since checkpoint) + 5` (overlap), capped at `windowDays*1440`. The first run uses the full window. Pages run sequentially, up to `maxPagesPerRun`. A remainder is enqueued as a continuation job carrying `nextPageToken`. The checkpoint (the max `updated` seen, stored as an ISO instant) is committed only after the last page of a run sequence | Relative minutes avoid JQL time-zone ambiguity. The overlap absorbs clock skew. A unique key absorbs duplicates |
| B6 | **Reconcile.** `jira.reconcile` runs every `reconcile.hours`. It runs the full scope JQL (`(<scope>) ORDER BY updated ASC`) across all pages. If and only if every page completed, it sets `in_scope = false` on stored issues not seen in that run, and `in_scope = true` on those seen. An incomplete reconcile changes no scope flags | Catches reassignment away and window expiry without false removals |
| B7 | **Exclusion guard.** Code appends `AND project not in (<excluded>)` to every JQL when `excludedProjects` is non-empty, and the store also drops any parsed issue whose project key is excluded. Keys are validated `^[A-Z][A-Z0-9_]+$` before use in JQL | "Never track that project" holds even if the scope JQL is edited carelessly |
| B8 | **Storage.** `jira_issues` columns: `key` (unique), `jira_id`, `project_key`, `summary`, `status_name`, `status_category` ('new'\|'indeterminate'\|'done'), `priority` (nullable), `issue_type`, `labels` (json), `due_date` (`YYYY-MM-DD`, nullable), `jira_created_at`, `jira_updated_at` (ISO UTC instants), `web_url`, `in_scope` (bool), `first_seen_at`, `last_seen_at`, `attention` (nullable enum), `attention_since` (nullable). An upsert changes only on new data, and `jira.issue_updated {key}` is published only when status, priority, due date, summary or assignee scope changes | Minimal and sufficient |
| B9 | **Attention rules** (pure `attentionOf(issue, now, settings)`, first match wins) apply only to `in_scope` issues that are not done: `overdue` (due date before today, local); `blocked` (status name in `blockedStatuses` case-insensitively, OR status name matches `/block/i`, OR a label matches `/^blocked$/i`); `due_soon` (due within `dueSoon.days`); `stale` (not updated for `stale.days`); else null. Done or out-of-scope gives null. When attention changes to non-null, publish `jira.issue_attention {key, attention}` | ADR doc "rules first" |
| B10 | **Slack correlation** is computed at read time. An issue's Slack mentions are stored messages whose text contains the key as a whole token (`\bKEY\b`, case-sensitive), newest 20. The issue view carries `slackMentions: { count, latest: [{messageId, conversationLabel, sentAt, permalink}] }` with no text. No new table | Cheap, and no stale links |
| B11 | **API:** `GET /api/jira/status` → `{enabled, cloudIdSet, lastSyncAt, lastReconcileAt, issueCount, lastError}`; `GET /api/jira/issues?view=attention\|open\|done\|all` (in-scope only; `done` = done within the window); `GET /api/jira/issues/:key` (404 when unknown); `POST /api/jira/sync` enqueues an incremental sync (409 when disabled). Settings are changed through a small `PUT /api/jira/settings` accepting `{enabled?, scopeJql?, excludedProjects?}`, validated (JQL max 500 chars, no newlines) | The user can see and trigger it. No arbitrary settings route |
| B12 | **Dashboard.** `counts.jiraAttention` (in-scope issues with non-null attention) is added. The pipeline is unchanged. In the web: a Jira section (nav between Commitments and People) with groups Needs attention / In progress / To do / Done recently. Each row: key (mono), summary, status chip, priority, due, updated relative time, Slack-mention count, and an "Open in Jira ↗" link (`webUrl`). A Needs-you card "JIRA · NEEDS ATTENTION" (one card listing up to 5 issues, with a "See all" link to the section) appears when `jiraAttention > 0`. When `jira.enabled` is false, a setup card "Connect Jira" shows the default scope and an Enable button | Matches the Phase 7 design language |
| B13 | **Untrusted text.** Issue summaries are untrusted (ADR-032). They are never put into a run that can act, are rendered as plain text, and are never logged | Rule 5 |
| B14 | **Smoke.** `scripts/dev/jira-smoke.ts` runs against a temp DB: it resolves the cloudId, then fetches one page of the configured scope, using the `--jql` argument or else the default. It prints counts only (issues, pages, statusCategory counts) and never keys or text | Real-connector proof, run by the controller |

## Out of scope

- Writes.
- Commitments from Jira.
- AI analysis.
- Issue comments and descriptions.
- Multi-site support beyond selecting the cloudId by hand.
